## 核心框架

### 框架 1：观察—实验—固化（第2版第12原则；S5=B；国家应用[改编]）

适用场景：港口滞留、交付延期、保修反复、备件等待等有可观察过程的问题。

步骤（伪代码）：

```
1. DEFINE 客户受影响的具体结果 + 当前差距
   → 保留时间窗与原始记录
2. OBSERVE 港口/仓库/交付/维修现场一条真实流程
   → 记录等待、返工、交接点；汇报表不能替代现场事实
3. HYPOTHESIZE 一个可检验的原因假设
   → 设下一阶段目标与约束
4. EXPERIMENT 小范围改变一个可控动作
   → 事先约定观察指标与失败判据
5. COMPARE 前后结果 + 核查同期外部变化
   IF 有效  → 更新流程与训练
   ELSE    → 保留学习，调整假设
```

输出：问题记录、事实/假设分栏、实验卡、责任人、复查日与标准更新。

### 框架 2：技术需求与试点门槛（第2版第8原则；[A级：Liker《When the Toyota Way Meets Industry 4.0》]；国家应用[改编]）

适用场景：CRM/ERP、库存看板、AI 经营助手、数字单证项目。

步骤（伪代码）：

```
1. DEFINE 业务问题、当前成本/错误率、已有流程及负责人
2. AUDIT  数据可得性、口径、维护责任、使用者能力
3. COMPARE 人工流程改善 vs 技术方案
   → 避免用"大屏存在"证明经营改善
4. PILOT  选一个国家/车型/流程试点
   → 预先定义基线、达标指标、回退与复核点
5. SCALE ONLY IF 业务改善证据 AND 人员接手条件同时满足
   ELSE 暂停或回退
```

输出：试点说明、成本与风险、指标、人工复核位置、扩大或暂停判断。

### 框架 3：战略与兑现能力对齐（第2版第13/14原则；S4=B；S3=A；国家应用[改编]）

适用场景：新车型上市、销量增长、服务网络扩展和国家经营年度计划。

步骤（伪代码）：

```
1. STATE   国家目标、客户承诺、外部不确定性
2. GAP     交付、服务、渠道人员、现金能力差距
3. DECOMPOSE 目标为跨职能行动
   → 记录负责人、资源、依赖、学习问题
4. PILOT   从有限试点学习
   → 大型投资必须另做商业和财务评估
5. REVIEW  定期比较承诺与实际能力
   → 更新计划并训练承担工作的人员
```

输出：目标—能力—动作表、资源约束、阶段门槛与复盘结论。

## 当代层：独立方法（非《丰田模式》原著；来源 E / 套件设计 D）

以下为独立当代方法，与丰田模式区分，不能归于 Liker 原著。

- **SCOR DS（E）**：借用 Orchestrate、Plan、Order、Source、Transform、Fulfill、Return 分类梳理职责与异常，不把参考模型当销量预测器。来源：ASCM SCOR DS。
- **销量—库存—现金协同（D/E）**：按周处理异常、按月协同需求/供应/资金；分开出口发运、渠道批发、终端交付、注册和回款。IBP/S&OP 仅作实践名称，不宣称获取完整标准或自行授予认证。
- **各车型配置库存追踪（D/E）**：追踪工厂待发、在途、港口、国家仓、经销商库存与库龄；统一 VIN/批次和货权口径，避免重计。期末实物库存 = 期初 + 实际到货 − 实际交付 ± 核实调整；可售库存另扣锁定/缺件/不可售项。
- **需求情景与缓冲（E）**：需求至少给基准、上行、下行情景，与简单预测基线比较；运期波动、备件服务水平与现金约束共同决定缓冲。**长途海运和进口不确定性下不机械追求零库存。**
- **电子单证（E）**：先确认承运人、银行、司法辖区和合同适用条件，测试签发/修改/控制权转移/交单/回退；扫描 PDF 不等于可转让 eBL。DCSA 集装箱标准不能直接推广为所有滚装航线。
- **售后上市门槛（D）**：诊断工具、技师训练、救援、关键备件、保修责任与升级路径齐备；阈值必须来自车型故障数据、补货周期和合同承诺，不虚构统一天数。

输出：销售/供应/现金情景表、瓶颈及负责人、采购/促销/发运建议、服务门槛与证据缺口。没有内部数据时只能给模板和假设区间。
