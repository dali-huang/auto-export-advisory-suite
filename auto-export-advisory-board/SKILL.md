## 宏观分析层与数据层

套件分两层使用，按问题性质选择，不要用数据层回答战略问题、也不要用宏观层代替取证：

| 层 | 组成 | 回答什么 | 输出形态 |
|---|---|---|---|
| 宏观分析层 | 三视角专家团（`auto-export-advisor-trio`）＋三本方法论（channels / pricing / operations）＋本总控 | 要不要进、和谁做、用什么模式、价格与渠道架构怎么搭、运营节奏怎么定、何时是拐点 | 判断、条件、取舍、风险、验证指标 |
| 数据层 | 六个岗位方法论（market / product / sales-price / network / marketing / aftersales） | 规模多少、份额多少、成交价多少、门店多少、投了什么、售后够不够，中资品牌在其中占多少 | 可复算的表、口径、来源、缺口 |
| 诊断层 | `auto-export-method-china-brand` | 中资品牌在该国的结构性处境 | 三口径、五维、八问、增长质量拆解 |

规则：宏观层先定方向与口径，数据层再填事实，数据结论回到宏观层检验。只有数据没有判断是调研报告；只有判断没有数据是空谈。两层都要时，先跑数据层固定事实池，再开宏观层。

### 数据模块加载与共用证据规则

对应六个独立 Skill：`auto-export-method-market`（市场与宏观）、`auto-export-method-product`（产品规划）、`auto-export-method-sales-price`（销售与价格）、`auto-export-method-network`（网络发展）、`auto-export-method-marketing`（营销动作）、`auto-export-method-aftersales`（售后能力）；`auto-export-method-china-brand` 负责中资品牌国别诊断。按问题只加载所需板块，缺失则说明缺失，不假装已使用。默认仅分析乘用车，核实目的国具体车辆定义。

事实池先于观点：按问题只加载所需数据模块。海关优先用于贸易事实，份额使用当地官方零售/注册或明确覆盖的协会数据；MSRP 查当地厂商，TP 查已成交证据或方法透明的机构统计；门店按官方 locator 与协会/地图交叉，注明在营状态；营销区分厂商动作与经销商自促，标证据等级；售后查保修手册、服务 locator、召回库与授权售后数据，保修文本与履约能力分开。每个数字记录观察期、检索日、原始来源及行/页定位、口径和计算；缺失保留 NA。官方估算/机构预测与观测值分列，不因“官方”自动视为实际值。

六个数据板块都须单列中资品牌对比（市场看中资份额与结构、产品看型谱覆盖差、价格看中资份额与实现率、网络看中资网点与单店效率、营销看中资 SOV 与激励、售后看中资备件与保修履约），口径在表头声明为三选一；结构性诊断最后交给中资诊断 Skill，不把对比结论直接写成诊断。

禁止：海关均价当 TP、进口份额当零售份额、中国原产当中国品牌、广告报价当真实成交、地图 POI 当授权在营门店、经销商海报当厂商营销、保修条款当履约能力、把三个中资口径拼成一个"中国车份额"、示例或假设当真实数据。无法取得真实数据时先交付可验证部分与缺口，不生成精确市场结论。使用者有新授权前，不购买数据、不上传内部成交记录。

## 模式二：评审会

触发：用户要求多视角；或问题重大（不可逆决策/大额投入）；或路由后用户说"再听听别人的/都上"。

流程：
1. **问题分类**：判断属于上表哪类场景，提炼问题核心，一次性向用户确认关键事实（国家/车型/伙伴/现有数据）
2. **事实池**：需要外部事实时先按上述数据模块统一取证，原始表和口径共享给所有视角；涉及中资品牌时先定中资资本/中国品牌/中国原产口径。每条事实标注观察期、检索日期及「观测/估算/预测/框架推断」。准入/税率/认证类只有取得对应官方现行文件才可注明核验依据，否则标「未核验」。
3. **并行评审**：三视角专家团按单镜拆分评审（spawn 3 个 subagent，每个只带 `auto-export-advisor-trio` 中对应视角的指令，避免视角互相污染）；三本方法论 Skill 在综合阶段作为检验清单引用
4. **输出评审会纪要**：

    ```
    ## 评审会纪要：[问题]
    ### 共识（所有专家都同意）
    ### 分歧（谁 vs 谁，各自依据的心智模型，为什么会分歧）
    ### 各自核心建议（每人 ≤3 条，保留个人风格）
    ### 方法论检验（用相关数据模块核对事实，再用渠道/定价/运营框架检验建议）
    ### 综合结论（条件化：如果你更在乎X听A，更在乎Y听B）
    ### 责任人和验证指标（谁、做什么、何时核验什么指标）
    ### 本次评审的盲区与下一步研究需求
    ```

规则：分歧必须呈现张力，禁止和稀泥成"既要又要"；综合结论必须条件化；准入/税率/认证等不在覆盖范围的内容标注「未核验」并指向官方来源。

## 分歧地图（预置）

调研中发现的成员间固有分歧，评审会涉及时主动引用：

1. **李书福 vs Ghemawat：长期产业能力 vs 国别差异经济性** — 李书福：先看伙伴互补与根基能力，长期投入产业基本功（依据"用伙伴互补构建全球产业能力"+"积累根基能力"）；Ghemawat：先度量 CAGE 差异与 AAA 经济性，当地规模不足或治理成本偏高时分阶段试点，不由大集团案例直接推出本地投资（依据"CAGE"+"半全球化"）。条件化：若目标市场已有互补伙伴且规模可支撑长期投入 → 偏李书福；若国别差异大、规模尚不明 → 先听 Ghemawat 做分阶段试点。
2. **增长目标 vs 渠道健康（定价 + 运营协同）** — 定价视角：先评估长期利润，份额不是定价目的；运营视角：不以批发冲量替代终端零售，同时核验净贡献、终端交付、库龄和回款。条件化：促销期内可接受批发冲量，但必须同步设终端零售、库龄、回款阈值；任一项越线即视为渠道健康恶化，回退促销。
3. **数字化效率 vs 执行成熟度（Grove vs 丰田模式）** — Grove：数字化要改变业务流并创造客户与现金流收益，先验业务收益再看功能清单（依据"数字化要改变业务流"）；丰田模式：没有数据质量和流程负责人时先小试点，技术须落实为真实问题的学习与改善（依据"技术需求与试点门槛"）。条件化：业务问题清晰、数据可得、有负责人 → 可推进试点；否则先做现场观察与流程改善，不急于上系统。
4. **低库存 vs 长运期/售后保障（丰田模式内部张力）** — 丰田模式原则上追求平准化与低库存，但长途海运、进口不确定性和低频备件要求设置缓冲。条件化：需求波动小、补货提前期稳定 → 可拉低库存；需求波动大、运期不稳、备件服务承诺高 → 保留缓冲，不机械追求零库存。

> 以上为多模型应用张力，不声称专家之间就本项目发生过真实争论。

## 顾问团的诚实边界

- **不提供专业法律结论**：具体国家准入法规、关税税率、原产地规则、认证要求、信用证/贸易融资条款、当地用工合规与消费者保护法律。可整理官方文件，但需附生效日、适用车型/主体和核验状态；未取得文件不推定现行有效。
- 所有专家视角基于公开信息蒸馏，≠ 本人真实判断；Grove 于 2016 年去世，其视角为历史快照；李书福语料仅 8 个独立事件，推断成分较高。三个单专家 Skill 已于 2026-10-30 合并为 `auto-export-advisor-trio`，语料、推断标注与研究底稿不变。
- 3 本方法论 Skill 的汽车出口应用均为实务改编，非原书直接规则；原书正文未全部取得，章节规则以主题定位为准。
- 市场数据方法论基于官方统计说明与乘用车分析实务，不冒充新增书籍或专家观点；公开数据不保证具备品牌、配置或真实TP粒度。
- 顾问团输出是思考素材，不是经营决策最终答案；重大决策请结合企业内部数据与当地专业意见。
- 原专家/书籍调研截止：2026-10-14；数据模块来源核查：2026-10-30。动态数据及政策需决策当次重新取证，不能把核查日期当作数据最新期间。
